# 7. Auth: Better Auth, generic JWT/JWKS, recipes

**Status:** Accepted, 2026-11-22

## Context

The first draft planned separate prebuilt resolvers for Clerk, Auth.js, Supabase, Firebase and JWT, each tracking its vendor's SDK changes. It also planned a Better Auth adapter for DynamoDB.

## Decision

Three ways to authenticate: Better Auth (first-class, `chat-better-auth`), one generic JWT/JWKS resolver in core, and `defineResolver`. Clerk, Supabase, Auth0, Firebase and Auth.js get docs recipes built on the JWT/JWKS resolver.

The Better Auth DynamoDB adapter is dropped from this project: it is an auth product, not chat.

## Consequences

- No vendor SDKs in core; one resolver covers most hosted auth providers.
- Recipes must be exercised, for example in example apps, so they don't rot.
